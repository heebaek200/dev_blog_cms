# 요구사항

## 1. 의뢰 배경

가상의 클라이언트 A씨는 자신이 학습하고 경험한 개발 지식을 공개할 수 있는 개인 기술 블로그를 원한다. 방문자는 별도 가입 없이 게시글을 읽고, A씨는 관리자 화면에서 콘텐츠를 직접 관리할 수 있어야 한다.

프로젝트는 하루 안에 실행 가능한 상태로 완성해야 한다. 많은 기능을 부분적으로 제공하기보다 확정된 핵심 기능이 처음부터 끝까지 정상 동작하는 것을 우선한다.

## 2. 대상 사용자

### 공개 방문자

- 로그인 없이 게시글 목록과 상세 내용을 조회한다.
- 카테고리와 태그를 이용해 관련 게시글을 조회한다.

### 관리자 A씨

- 최초 관리자 계정 하나로 로그인한다.
- 게시글, 카테고리와 태그를 관리한다.
- 관리자 계정을 추가하거나 방문자의 회원가입을 받지 않는다.

## 3. 기능 요구사항

### 게시글 조회

- 방문자는 공개된 게시글 목록을 조회할 수 있어야 한다.
- 방문자는 공개된 게시글의 제목, 본문, 작성 시각, 수정 시각, 카테고리와 태그를 확인할 수 있어야 한다.
- 방문자는 특정 카테고리 또는 태그에 속한 공개 게시글을 조회할 수 있어야 한다.
- 초안 게시글은 방문자에게 노출되면 안 된다.

### 관리자 인증

- A씨는 최초 관리자 계정으로 로그인하고 로그아웃할 수 있어야 한다.
- 로그인하지 않은 사용자는 관리 기능에 접근할 수 없어야 한다.

### 게시글 관리

- A씨는 게시글을 초안으로 저장하거나 공개할 수 있어야 한다.
- A씨는 초안과 공개 게시글을 수정하고 삭제할 수 있어야 한다.
- 예약 발행과 삭제한 게시글 복구 기능은 제공하지 않는다.

### 카테고리와 태그

- 게시글에는 카테고리를 지정하지 않거나 하나만 지정할 수 있어야 한다.
- 게시글에는 태그를 지정하지 않거나 최대 5개까지 지정할 수 있어야 한다.
- A씨는 카테고리와 태그를 생성하고 삭제할 수 있어야 한다.
- 사용 중인 카테고리와 태그는 삭제할 수 없어야 한다.
- 이름의 앞뒤 공백을 제거한 뒤 같은 이름의 카테고리나 태그가 중복 생성되면 안 된다.

### 오류 처리

- 존재하지 않는 화면이나 게시글에 접근하면 이해하기 쉬운 오류 화면을 표시해야 한다.
- 처리할 수 없는 주요 오류가 발생하면 내부 정보를 노출하지 않는 오류 화면을 표시해야 한다.

## 4. 범위 밖 기능

- 공개 회원가입과 다중 작성자
- 댓글과 좋아요
- 이미지·파일 업로드
- 전문 검색과 단순 제목 검색
- 페이지네이션
- 예약 발행과 삭제 복구
- 배포

검색 입력창, 검색 버튼, 페이지 번호와 이전·다음 버튼 등 미구현 기능을 암시하는 화면 요소도 제공하지 않는다.

## 5. 인수 기준

다음 조건을 모두 충족하면 A씨의 요구사항을 충족한 것으로 판단한다.

1. 전체 Build와 자동 Test가 성공한다.
2. 애플리케이션이 로컬에서 정상 실행된다.
3. 방문자가 공개 게시글 목록·상세와 카테고리·태그별 게시글을 조회할 수 있다.
4. 초안 게시글은 방문자에게 노출되지 않는다.
5. A씨가 로그인·로그아웃하고 게시글·카테고리·태그를 관리할 수 있다.
6. 비로그인 사용자의 관리 기능 접근이 차단된다.
7. 잘못된 주소와 주요 오류가 정해진 오류 화면으로 처리된다.
8. 실제 비밀번호나 데이터베이스 접속정보가 저장소에 포함되지 않는다.
