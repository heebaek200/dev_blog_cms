# 사용자 시나리오 및 업무 규칙

## 사용자 역할

### 공개 방문자

- 로그인 없이 게시글 목록과 상세 내용을 조회할 수 있다.
- 게시글, 카테고리와 태그를 변경할 수 없다.

### 관리자

- 관리자는 한 명만 존재한다.
- 최초 관리자 계정은 환경변수로 전달한 정보로 생성한다.
- 최초 관리자 계정이 이미 존재하면 다시 생성하지 않는다.
- 로그인한 관리자는 게시글을 작성, 수정하고 삭제할 수 있다.
- 로그인한 관리자는 게시글에 사용할 카테고리와 태그를 관리할 수 있다.

## 게시글 상태와 전환

- 게시글 상태는 `DRAFT`와 `PUBLISHED`만 사용한다.
- 새 게시글은 초안으로 저장하거나 즉시 공개할 수 있다.
- 관리자는 초안을 공개하고, 공개 게시글을 다시 초안으로 전환할 수 있다.
- `DRAFT` 게시글은 관리자에게만 보이고 공개 방문자에게는 보이지 않는다.
- 예약 발행, 발행 마감과 삭제 복구는 사용하지 않는다.
- 게시글은 상태와 관계없이 물리 삭제하며 삭제 후 복구하지 않는다.

## 카테고리와 태그

- 게시글은 카테고리를 지정하지 않거나 하나만 지정한다.
- 게시글은 태그를 지정하지 않거나 최대 5개까지 지정한다.
- 카테고리와 태그 이름은 앞뒤 공백을 제거한 값을 사용한다.
- 정규화한 같은 이름의 카테고리 또는 태그를 중복 생성할 수 없다.
- 게시글에서 사용 중인 카테고리 또는 태그는 삭제할 수 없다.

## 정상 사용자 시나리오

### 공개 게시글 조회

1. 공개 방문자가 게시글 목록 또는 카테고리·태그별 목록을 요청한다.
2. 시스템은 `PUBLISHED` 상태인 게시글만 조회한다.
3. 방문자가 게시글을 선택하면 공개된 상세 내용을 표시한다.

### 관리자 로그인과 로그아웃

1. 관리자가 로그인 Form에 최초 관리자 계정 정보를 입력하고 POST로 요청한다.
2. 인증에 성공하면 관리자 Session을 만들고 관리자 게시글 목록으로 Redirect한다.
3. 관리자가 POST로 로그아웃을 요청하면 Session을 무효화하고 공개 게시글 목록으로 Redirect한다.

### 게시글 관리

1. 관리자 게시글 목록에는 `DRAFT`와 `PUBLISHED` 게시글을 모두 표시하고 상태를 구분한다.
2. 관리자는 작성·수정 Form에서 초안 저장 또는 공개를 선택한다.
3. 저장이나 수정에 성공하면 해당 관리자 목록 또는 게시글 화면으로 Redirect한다.
4. 삭제에 성공하면 관리자 게시글 목록으로 Redirect한다.

### 카테고리와 태그 관리

1. 관리자는 정규화했을 때 중복되지 않는 카테고리와 태그를 생성한다.
2. 게시글 작성·수정 시 카테고리를 0개 또는 1개, 태그를 0개부터 5개까지 지정한다.
3. 사용하지 않는 카테고리와 태그는 삭제할 수 있다.

## 예외 시나리오와 처리 규칙

### 인증 실패와 접근 차단

- 로그인 실패 시 아이디 또는 비밀번호 중 어느 값이 틀렸는지 구분하지 않는 동일한 메시지를 표시한다.
- 로그인하지 않은 사용자가 관리 화면이나 관리 요청에 접근하면 로그인 화면으로 Redirect한다.
- 로그아웃 이후 기존 Session으로 관리 기능을 사용할 수 없다.

### 게시글 접근과 입력 오류

- 공개 방문자가 `DRAFT` 게시글 주소에 직접 접근하면 게시글 존재 여부를 드러내지 않고 404 화면을 표시한다.
- 존재하지 않는 게시글, 카테고리 또는 태그를 조회하면 404 화면을 표시한다.
- 작성·수정 입력이 올바르지 않으면 저장하지 않고 Form에 오류 메시지와 기존 입력값을 다시 표시한다.

### 중복과 삭제 충돌

- 정규화한 이름이 같은 카테고리나 태그가 이미 있으면 새 항목을 만들지 않고 중복 원인을 안내한다.
- 게시글에서 사용 중인 카테고리나 태그의 삭제 요청은 처리하지 않고 사용 중임을 안내한다.
- 데이터베이스의 고유 제약조건을 최종 중복 방지 수단으로 사용한다.

### 중복 요청 방지

- 생성, 수정과 삭제 성공 후에는 화면을 직접 반환하지 않고 Redirect한다.
- Redirect 이후 새로고침은 이전 변경 요청을 다시 실행하지 않는다.

## 연계 설계 반영 사항

- 관리자 Session에는 관리자 식별자와 사용자명만 저장하며, 로그아웃 시 Session을 무효화한다.
- Form 입력 검증은 Bean Validation과 `BindingResult`를 사용하고, 업무 규칙 검증은 Service에서 처리한다.
- 성공, 경고와 오류 메시지는 RedirectAttributes의 Flash Attribute와 공통 Message Box로 표시한다.
